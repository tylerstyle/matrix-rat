## Minor Non-Blocking Notes

1. **CLI `--profile` placement with `doctor` (`src/main.rs:56-63`):** `#[arg(long, default_value = "default")] profile: String` does not set `global = true`, so `matrix-rat --profile work doctor` works (`src/main.rs:171`) whereas `matrix-rat doctor --profile work` is rejected by `clap`. Since config and themes are shared across profiles (`--profile` only selects store/log paths, which `doctor` never touches), this is harmless, though `global = true` would accept both orders.
2. **`read_config` error classification (`src/doctor.rs:588-593`):** Any `Err(_)` from `Config::load(file)` sets `config_broken = true` (`"the file is not valid TOML"`). Intentionally discarding the underlying `anyhow::Error` keeps paths and quoted file contents out of the report (`src/doctor.rs:933-938`), at the minor cost of reporting permission or non-UTF-8 read errors under the same wording.
3. **Unpaired mode resets in `ask_for_doctor` (`src/terminal.rs:174-182, 255-279`):** `ask_for_doctor` calls `guard.alternate_screen()`, which sets `ACTIVE = true` without enabling mouse, bracketed paste, or focus reports, so `drop(guard)` -> `restore()` emits `DisableFocusChange`, `DisableBracketedPaste`, and `DisableMouseCapture`. Those DEC private mode resets are idempotent (unlike the stack operations `PopKeyboardEnhancementFlags` and `POP_TITLE`, which are now properly guarded by `KEYBOARD_PUSHED` and `TITLE_PUSHED`).
4. **Long `◂ value ▸` glyph overlap with `▲`/`▼` when scrolled (`src/ui/modal.rs:278-293, 389-398`):** In `settings()`, `room = 36`, so a theme name of 32+ columns puts `" ▸"` right up to `rect.right() - 1`, where `▲` or `▼` draws if that row sits on the top or bottom visible line while scrolled (for example `ThemeLight` on the top row when scrolled down with pairing enabled). The `HitId::Setting(index, 1)` click target is already recorded before `▲`/`▼` is rendered.

## Checklist Verification

### 1. Piece E — Resilient `Config::parse` (`src/config.rs`, `src/app.rs`, `README.md`)
- `Config::parse` (`src/config.rs:250-276`) parses the file as a `toml::Table` first, so malformed TOML or duplicate keys still return `Err` (`Config::load` refuses broken files at startup as documented in `README.md:315-317`).
- When full-table `try_into::<Config>()` fails, each top-level key is tested alone against `Config` (`src/config.rs:257-270`). Failing keys are removed from the table, keep their defaults, and are recorded in `Config::ignored` while all valid settings and `[keys]` (parsed via `toml_edit::DocumentMut` for order preservation) stay in effect.
- Because `Config` (`src/config.rs:10-72`) carries `#[serde(default)]` without `#[serde(deny_unknown_fields)]`, unknown keys succeed per-key deserialization (`not_a_setting = 1` test at `src/config.rs:706-708`) and never enter `ignored` — ensuring `ignored`, `Config::ignored_notice()` (`279-293`), startup logs (`src/app.rs:564-566`), and `doctor` can only ever hold our own setting names.
- Invalid `preset` / `[keys]` entries (`Option<toml::Value>`) continue to pass `Config` deserialization and flow into `Keymap::from_config` warnings (`key_problems`), merged with `ignored_notice()` into a single startup toast (`src/app.rs:563-579`).

### 3. Piece D — Unread Count in Window Title & Terminal State (`src/app/title.rs`, `src/terminal.rs`, `src/app.rs`)
- **Title computation (`src/app/title.rs`):** `unread_count` sums `u64::from(room.unread)` across `!room.muted && !room.is_pending()` using `saturating_add` (excluding muted rooms, invites, knocks, and manually bold/marked-unread rooms with `unread == 0`; unaffected by DND; no room names). `take_window_title` emits `"matrix-rat"` or `"matrix-rat ({n})"` only when changed from `title_written`.
- **Title stack & `KEYBOARD_PUSHED` (`src/terminal.rs`, `src/app.rs:4860-5036`):**
  - `PUSH_TITLE` (`\x1b[22;0t`) and `POP_TITLE` (`\x1b[23;0t`) match `SetTitle` (`OSC 0`, window + icon title together). With `window_title = false` at startup, `TITLE` and `TITLE_PUSHED` remain `false` and the terminal title is never touched.
  - `KEYBOARD_PUSHED` and `TITLE_PUSHED` are set only by `write_activation()` / `resume()` (and `set_window_title(true)` while `ACTIVE`). Consequently, `ask_for_doctor()` (`TerminalGuard::enter(false, false)` + `alternate_screen()`, no `activate()`) and any panic or error between `enter()` and `activate()` never pop the outer shell's keyboard flags or window title stack.
  - **Restore paths audited:**
    - *Exit / `Ctrl-C` / `SIGTERM` / `SIGHUP` / `Err` return from `run()`:* `TerminalGuard::drop` calls `restore()` (`248-279`), popping `KEYBOARD_PUSHED` (if set), leaving altscreen, popping `TITLE_PUSHED` (if set), and disabling raw mode.
    - *Suspend (`Ctrl-Z`, `src/terminal.rs:214-218`, `src/app.rs:4911-4920`):* `suspend()` calls `restore()` before `SIGTSTP`, re-runs `resume()` (`enable_raw_mode` + `write_activation()`) on resume, and `app.window_title_lost()` clears `title_written` so the title is rewritten on the next draw.
    - *External `$EDITOR` (`src/terminal.rs:223-246`, `src/app.rs:4921-4948`):* `release()` calls `restore()` before spawning the editor, `resume()` re-activates and re-pushes stacks afterward, `app.window_title_lost()` clears `title_written`, and `resumed?` propagates errors after `finish_editor()` (dropping `guard` on error).
    - *Panic hook (`src/terminal.rs:281-297`):* Calls `restore()` first via atomic `.swap(false, Ordering::SeqCst)` flags, making double-restores (e.g. panicking while released or during drop) idempotent without double-popping stacks.
    - *Runtime `window_title` setting (`src/app.rs:1147-1153, 4967, 4994`):* Toggling off clears `title_written = None`; `terminal::set_window_title(false)` immediately emits `POP_TITLE` on the next loop pass before drawing. Toggling on re-pushes `PUSH_TITLE` and writes the title on the next draw. Collected in `Setting::ALL` and the command palette (`src/palette.rs:1441-1447`).
